## Detector rule and proof status

For a test t, D(t) is its set of contractual fault classes actually distinguishable from the inspected fixtures/assertions, partitioned by input. `fault_class` records those subsets; source-shape or weak controls are explicitly labelled. A proposed removal is admissible only if every partition's D(t) is contained in concrete independent remaining executable owners, and representative old/new fault witnesses preserve that detection. An equal name, a shared production helper, green after deletion, counts, source hashes and coverage alone are not containment evidence.

Every CSV experiment is **PLAN ONLY, NOT EXECUTED**. For each proposed assertion/helper simplification, execute the same valid fixture and isolated fault in baseline and candidate, then enable the precise accept-that-invalid-input regression. Both suites must fail the contractual mutant; a prose/layout-only mutant should fail only the baseline lock. Unexpected exceptions or fixture setup failures are not a detection win. For an actual merge/delete, additionally execute the named remaining owner without the removed method and prove its fault witness fails. No such merge/delete is approved here.

The independently held expected raw bytes/digest joins stay: packet/part/report/receipt identities, candidate/source and environment canonicalization, PE/MVID, predecessor history, XML seals, uploaded P/A/I and exported raw receipt digests. A digest length, repeatability or self-consistent rehash is not content or execution correctness. The source fingerprint repeatability Fact is explicitly weak; the source-only 43-name declaration census is explicitly not oracle execution.
