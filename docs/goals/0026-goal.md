/goal
Make FunnySharp useful for turning untrusted, nested application input into trusted domain values through reusable, composable decoders, building on the existing Result, Validation and located traversal semantics. Completion means a consumer can decode a nested order request with independently invalid fields and list elements, receive deterministic errors with useful field and element locations, and obtain the domain object directly on success without manually unpacking carriers or assembling paths. Independent checks must accumulate their errors while a step that requires a successfully decoded value must not run after that prerequisite fails; optional, missing, explicit-null, malformed and empty inputs must have deliberate, distinguishable behavior. Decoders must be reusable without leaking invocation state, must not turn cancellation or arbitrary programming exceptions into ordinary invalid input, and must support asynchronous work only where actual asynchronous input or validation makes it meaningful. Establish whether the experimental Location surface can honestly support this use, making its stability and allocation costs explicit rather than assuming it is allocation-free. Completion evidence is an executable consumer and discriminating examples for those boundaries, with equivalent ordinary C# and direct existing-Validation versions that include construction, adapters and error mapping in the consumer-code comparison; the maintainer judges whether expression and diagnosis improve, and relevant measurements disclose allocations, copying and execution costs. Retain BCL inputs and caller-defined errors and domain types, .NET 10 as the current supported baseline, optional immutability and thin I/O boundaries. This goal delivers a useful decoder capability without requiring an introspectable schema, a new serializer, a general effect runtime or the original conversation; structured contract derivation is a separate outcome in 0027-goal.md.
