/goal
Enable a FunnySharp consumer to express supported data constraints once and reuse that description for decoding or validation, structured explanations, schema metadata and useful generated test inputs with shrinking. The intended advance beyond a callable decoder is an inspectable contract whose known structure can serve several consumers without duplicating the same field, alternative, range and cardinality facts. Completion means a nested domain contract demonstrably drives those uses consistently, including invalid boundary inputs, and its owner can understand which capabilities are supported for each kind of rule. Arbitrary predicates and transformations must remain usable without inventing an inverse, generator, purity proof or complete schema for them: unavailable derivations must be explicit and have an honest caller-supplied extension path. Generated values must respect the declared supported constraints, shrinking must preserve the relevant valid-input domain when that is required, recursive generation must terminate within an explicit budget, and cross-field constraints must not silently become ineffective rejection sampling. Type shape alone must never be presented as proof of a business invariant. Completion evidence includes the same contract exercised across its supported interpretations, counterexamples for unsupported derivations and independent business properties or a reference implementation so agreement among generated artifacts is not treated as proof of correctness. The maintainer evaluates full consumer-code duplication and diagnostics against separate ordinary C# implementations, with runtime and generation costs disclosed. Keep resulting types and errors interoperable with Result, Validation, BCL and ASP.NET Core, and keep testing or compiler dependencies out of the core runtime dependency set. Goal 0026 supplies the decoding outcome where reused; do not require one universal schema for unrelated application code, automatic JSON wire-format changes or a custom language. Clojure spec and MoonBit derive are design references, not feature-parity obligations.
