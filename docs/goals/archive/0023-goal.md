/goal
Produce a release-quality FunnySharp preview candidate whose packages, public API, documentation, and evidence consistently express the accepted product constitution without expanding scope during release hardening. Completion means all stable APIs have intentional names, generic parameter order, nullability, exception and cancellation contracts, sync/async relationships, XML documentation, and compatibility commitments; experimental APIs are unmistakable and do not silently acquire the same stability promise. Quick starts and primary guides must present the canonical Option, Result, UnitResult, Validation, functional grammar, collection, async/streaming, concurrency, advanced-pattern, analyzer, performance, and ASP.NET Core usage, and every documented code sample must compile. Package dependency boundaries must remain BCL-first and contain no competitor dependency or compatibility surface; package metadata, versioning, API-compatibility baseline, release notes, trimming, Native AOT, and supported-runtime claims must be verified through external package consumers. Benchmark and AI-usability claims must link to their reproducible evidence and may not exceed it. General discriminated unions remain outside the candidate until the official .NET design and a separate accepted goal justify them. Evidence includes clean restore/build/xUnit v3/package results, compiled documentation, public API and dependency inventories, package-consumer compatibility results, trim and Native AOT evidence where claimed, and a fail-closed release-readiness record. Actual publication to an external feed requires separate explicit authorization and is not implied by this goal.
