/goal
Make FunnySharp's Option, Result, Validation, effects, and asynchronous composition convenient at ASP.NET Core boundaries without coupling the core library to ASP.NET Core. Completion means a separately consumable integration surface can map successful and failed domain outcomes to IResult and RFC-compatible ProblemDetails with explicit, configurable status/error mappings; it supports Minimal APIs, request cancellation, asynchronous handlers, and validation errors without hidden service location or global exception swallowing. Domain code must remain usable without HTTP concepts, and consumers must be able to override policy rather than inheriting surprising magic conventions. Evidence must include xUnit v3 integration tests exercising representative success, not-found, validation, domain-failure, unexpected-exception, and cancellation paths in a real ASP.NET Core test application, plus compiling examples that demonstrate a materially simpler endpoint while preserving visible control flow.
