/goal
Add an accumulating validation model and collection-level traversal semantics that clearly distinguish independent error accumulation from Result's fail-fast behavior. Completion means users can validate independent inputs, preserve deterministic error order, combine all applicable failures, and sequence or traverse Option, Result, and Validation values across standard synchronous and asynchronous .NET sequences. Empty inputs, large inputs, multiple enumeration, short-circuiting, cancellation, asynchronous failure, and ordering must have explicit and tested behavior. The public API must avoid a parallel collection hierarchy and use BCL collection/sequence primitives wherever their semantics are sufficient. Evidence must include xUnit v3 tests demonstrating the relevant applicative/monadic laws and edge cases, compiling examples for request/domain validation, and measurements that expose allocation or buffering costs rather than disguising them.
