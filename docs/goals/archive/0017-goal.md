/goal
Make FunnySharp's collection programming substantially safer and more expressive while keeping standard .NET collections and sequence types as the ecosystem. Completion means callers can express total cardinality-sensitive operations, non-empty guarantees where they create real safety, selection and partitioning, fold and scan, exact versus truncating combination, and Option, Result, UnitResult, and Validation traversal without manually unpacking wrappers or losing collection shape. Empty, singleton, duplicate, multiple-match, unequal-length, large-input, deferred-execution, and repeated-enumeration behavior must be distinguishable rather than collapsed into convenient but lossy absence. Traversal failures must be able to retain useful index, key, item name, property path, and nested location context so that a failure such as customers[17].addresses[2].postalCode can be produced compositionally instead of assembled by application code. Ordering, short-circuiting, accumulation, allocation, buffering, disposal, and cancellation must be explicit for every supported carrier. Span and Memory paths may exist only where their lifetime and mutation semantics stay honest; they must not be falsely unified with asynchronous streams. Evidence includes xUnit v3 edge, law, and enumeration tests; realistic data-cleaning and batch-validation examples; public shape and naming documentation; and performance/allocation comparisons with equivalent LINQ, loops, and BCL collection operations. A custom general collection hierarchy is excluded.
