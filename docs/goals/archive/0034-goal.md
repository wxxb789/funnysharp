/goal
Make independently reusable sequence summaries composable into one evaluation over a source, so a consumer can combine count, sum, extrema and a domain-specific summary without hand-writing a monolithic accumulator or enumerating a single-pass input repeatedly. Completion means those summaries can be defined and understood independently, combined into a typed result and evaluated over BCL sequence inputs with one traversal and isolated execution state. Empty extrema, numeric overflow, ordering, mutable seed reuse, exceptions, cancellation and any early-completing component must have deliberate semantics; the composition must not stop a source while another required component still needs it. A synchronous calculation should remain reusable when only input acquisition is asynchronous. Completion evidence compares combined execution with separate summaries and a reasonable hand-written single-loop baseline, including state size, delegate overhead, allocations and large-value copying; the maintainer judges whether reusable composition improves complete consumer code without an unexplained performance tax. General equivalence claims must respect actual numeric and exception semantics rather than assuming mathematical associativity for arbitrary machine arithmetic. Assess the previously proposed state-plus-output transformation, often called MapAccum, against existing Scan plus Select: include a distinct public operation only if a real consumer demonstrates useful state isolation or expression gains, and record an explicit non-adoption finding otherwise. Keep BCL containers, optional local mutation and caller-owned storage where appropriate. This goal does not require a public typeclass hierarchy, automatic parallelism, a replacement LINQ implementation or the compile-time optimization experiment in 0039-goal.md.
