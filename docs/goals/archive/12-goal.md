/goal
Bring the implemented FunnySharp feature set to a coherent, release-quality state for .NET 10+ without expanding its accepted scope. Completion means the public API has consistent naming, generic parameter order, nullability, cancellation placement, sync/async pairing, XML documentation, examples, and package boundaries; all documented snippets compile and the primary guides cover function composition, Option/Result/Validation, data pipelines, state machines, effects/resource safety, concurrency, opt-in immutability, and ASP.NET Core integration. Packages must have intentional dependencies and metadata, and their trimming, Native AOT, and supported-runtime behavior must be evaluated and accurately documented. The repository must expose reproducible xUnit v3 test and benchmark evidence, including comparisons with relevant BCL baselines, without claiming performance not demonstrated by the data. Analyzers and a general discriminated-union implementation remain deferred; the documentation must explain the C# 15/.NET 11 union dependency and the conditions for reconsidering a net10.0 compatibility layer. Evidence must include clean build/test/package results, compiled documentation samples, API and dependency inventories, compatibility results, and a release-readiness checklist with no unresolved critical item hidden behind prose.
