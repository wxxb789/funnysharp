/goal
Give FunnySharp a small, coherent, and C#-idiomatic function-composition surface covering piping, composition, currying, partial application, argument reordering, and side-effect observation without turning the library into an overload or delegate-type universe. Completion means common synchronous and asynchronous functions can be composed with useful type inference, predictable evaluation order, exception and cancellation behavior, and no sync-over-async; Task and ValueTask behavior is correct where asynchronous forms are meaningful. The API must prefer standard delegates and .NET primitives, avoid runtime reflection or dynamic dispatch on normal paths, and keep uncommon arities or convenience overloads from dominating discoverability and maintenance cost. Evidence must include compiling usage examples, xUnit v3 tests for composition laws and edge cases, and allocation/throughput comparisons with equivalent direct C# delegate code, with material trade-offs made visible rather than hidden.
