/goal
Give FunnySharp one small, orthogonal, and predictable functional API grammar that lets developers and coding agents express common C# workflows with materially less consumer-side semantic LOC without hiding control flow or runtime cost. Completion means every stable verb has one primary meaning and predictable output shape across the carriers where that meaning is valid; function piping, composition, currying, partial application, fallible-function composition, observation, recovery, folding, and related workflow operations have inference-friendly signatures and one documented canonical usage. Synchronous and asynchronous forms must share concepts without proliferating carrier-derived names, aliases, or mechanically generated overload families; any LINQ syntax bridge remains secondary to the canonical vocabulary. A reader must be able to infer evaluation order, short-circuiting, exception, cancellation, enumeration, and materialization behavior from the signature and contract. The surface must avoid reflection, dynamic dispatch, hidden scheduling, HKT simulation, operator tricks, and magical implicit conversions on normal paths. Evidence includes an authoritative grammar table, compile-time ambiguity and inference tests, public API diff and inventory, and representative side-by-side workflows showing that FunnySharp code is shorter while maintainers judge it at least as explicit and readable as idiomatic C#. Raw line count alone is not completion evidence.
