/goal
Make nested data integration concise and predictable with FunnySharp by allowing a consumer to extract typed fields, expand nested records while retaining parent context, align parallel child sequences exactly and carry useful source locations through the transformation. Completion means a realistic nested import can reach ordinary typed rows with explicit policies for missing fields, nulls, empty child collections, unequal child lengths and rejected items, and a failure can identify its originating record and nested element without application-built path strings. Aligned expansion must be distinguishable from Cartesian expansion, and each operation must state its output shape, ordering, cardinality, enumeration, buffering and partial-output behavior. Support useful synchronous and asynchronous sources without pretending Span lifetimes can cross awaits or borrowed JsonElement values outlive their document. Provenance must have a disclosed cost and an appropriate minimal form for callers who only need failure locations rather than a complete per-row execution trace. Completion evidence compares a full import using existing LINQ, loops and BCL JSON facilities with the proposed consumer, exercising shape and data-loss boundaries and measuring materialization and location overhead; the maintainer judges expression, error usefulness and complete consumer-code reduction. Reuse decoders and located errors from Goals 0026-0027 and constrained joins from 0035 where they are actually needed, while keeping independent reshaping useful. Retain standard .NET records and sequence types, explicit data-conversion policy and optional immutability; do not recreate R's dynamic evaluation, a serializer, a DataFrame engine or automatic lossy type coercion.
