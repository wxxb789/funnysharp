/goal
Give FunnySharp an explicit, typed failure model suitable for pragmatic Railway Oriented Programming without making exceptions or a custom effect runtime the default control-flow mechanism. Completion means Result values can be created, matched, mapped, bound, error-mapped, validated, recovered, combined in fail-fast flows, and composed through synchronous and asynchronous functions with consistent semantics. Boundary helpers may convert exception-throwing .NET APIs into explicit failures, but cancellation must not be accidentally converted into an ordinary domain error and exception identity/stack information must not be silently destroyed. The API must interoperate naturally with Option, standard delegates, Task, ValueTask, and idiomatic C# query or pipeline syntax where that improves clarity. Evidence must include xUnit v3 law and edge-case tests, examples replacing realistic nested if/else and try/catch flows, and performance/allocation comparisons with straightforward imperative C#.
